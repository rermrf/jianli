# 技能熟练度结构化设计

## 概述

当前“个人技能”仅以标签形式展示，无法体现技能熟练度和使用场景。本次改动将技能从 `string[]` 升级为结构化数据，在编辑页、展示页、打印页统一支持技能名称、熟练度和简短说明。

## 目标

- 技能数据支持 `name`、`level`、`summary`
- 展示页将技能标签升级为技能卡片
- 打印页同步展示技能熟练度与说明
- 编辑页支持新增、删除、修改技能及其熟练度
- 对已有旧数据 `string[]` 做兼容映射，不要求手工清库

## 数据结构

技能项结构：

```json
{
  "name": "Go",
  "level": "掌握",
  "summary": "API、并发、服务治理"
}
```

熟练度固定三档：
- `掌握`
- `熟悉`
- `了解`

`ResumeData.skills` 从 `string[]` 调整为技能对象数组。

## 兼容策略

为兼容旧简历数据：
- 如果前端读取到旧格式 `skills: string[]`
- 自动映射为：
  - `name`: 原字符串
  - `level`: `掌握`
  - `summary`: 空字符串
- 后续保存统一写回新格式

## 展示设计

### 展示页

技能区域改为技能卡片：
- 技能名
- 熟练度标签
- 一行简短说明

移动端可单列堆叠，桌面端可双列或多列。

### 打印页

打印页保留技能区，但改为更紧凑排版：
- 技能名
- 熟练度
- 说明

不使用进度条，不使用星级。

## 编辑页设计

“个人技能”改为结构化列表编辑：
- 技能名称输入框
- 熟练度下拉框
- 技能说明输入框
- 新增技能按钮
- 删除技能按钮

熟练度只允许从固定三档里选择，避免自由输入导致数据不统一。

## 非目标

- 不做进度条/星级表示
- 不做复杂技能分类
- 不做技能排序拖拽

## 测试边界

### 前端

至少覆盖：
- 旧 `string[]` 技能能兼容映射为新结构
- 编辑页可新增、删除、修改技能项
- 展示页显示技能熟练度和说明
- 打印页显示技能熟练度和说明

### 人工联调

需确认：
- 编辑页改完后保存成功
- 首页能清楚看出技能层级
- 打印页排版没有被技能说明撑坏

## 验收标准

满足以下条件视为完成：
- 技能数据已升级为结构化格式
- 展示页不再只是纯标签
- 熟练度以三档统一展示
- 编辑页可维护熟练度与说明
- 兼容旧数据
- 前端测试通过
