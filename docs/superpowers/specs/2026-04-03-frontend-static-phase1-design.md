# 阶段一前端静态还原设计

## 概述

本阶段只实现前端静态页面还原，不接入真实后端接口，不做真实鉴权校验，不做真实 PDF 导出。

目标是基于现有 Pencil 设计稿与总方案文档，在 `web/` 下完成一个可运行的 React + TypeScript + React Router + Tailwind CSS 前端原型，覆盖移动端和 PC 端响应式布局，并提供由本地 mock 数据驱动的轻交互能力。

本设计是对总方案文档的阶段化落地，当前只覆盖前端静态层，不改变后续 Go + Gin + SQLite 的整体方向。

## 目标

- 还原 5 个静态路由页面：`/`、`/edit`、`/visitors`、`/login`、`/print`
- 对齐 Pencil 设计稿中的移动端与 PC 端布局结构、信息层级和视觉风格
- 使用本地 mock 数据驱动页面内容，避免把页面写死在 JSX 中
- 提供最小但真实可用的前端交互：登录跳转、路由守卫、编辑保存、访客筛选、打印页跳转
- 为第二阶段接入真实 API 保留清晰的页面边界、数据边界和状态边界

## 非目标

- 不接入 `/api/*` 真实接口
- 不实现真实 `X-Auth-Key` 校验
- 不生成真实 PDF 文件
- 不引入后端服务、数据库或导出流程
- 不在本阶段做完整设计系统抽象

## 技术约束

- 工程基础：Vite + React + TypeScript
- 路由：`react-router-dom`
- 样式：Tailwind CSS
- 页面适配断点：
  - `< 768px` 视为移动端
  - `>= 768px` 视为 PC 端
- 当前交互状态仅保存在浏览器 `sessionStorage` 和 `localStorage`

## 总体方案

采用“页面 + 共享组件 + mock 数据 + 本地状态”的中间方案，而不是把所有逻辑直接写在单个页面里，也不提前投入完整设计系统抽象。

这样做的原因：

- 比“页面内全部写死”更利于后续接 API
- 比“先做完整组件体系”更快，更适合当前第一阶段
- 能让展示页、编辑页、打印页共享同一份简历草稿来源
- 能让访客页单独使用 mock 数据，不与简历编辑状态耦合

## 页面范围

### 1. `/` 简历展示页

用途：公开展示简历内容。

布局：

- 移动端为单栏纵向滚动布局
- PC 端为顶部导航 + 左右双栏布局

内容：

- 个人信息
- 技能标签
- 工作经历
- 项目经历
- 教育经历
- 荣誉奖项
- 导出打印入口

交互：

- 点击“导出 PDF”按钮跳转到 `/print`
- PC 端导航中展示前往编辑页和访客统计页的入口

### 2. `/edit` 简历编辑页

用途：在前端本地修改简历草稿。

布局：

- 移动端为纵向表单
- PC 端为左右双栏编辑工作台

内容分区：

- 基本信息
- 技能编辑
- 工作经历
- 项目经历
- 教育经历
- 荣誉奖项

交互：

- 支持技能新增、删除
- 支持工作经历、项目经历、教育经历、奖项的新增和删除
- 支持文本字段编辑
- 支持保存草稿到 `localStorage`
- 保存后给出轻量成功反馈

### 3. `/visitors` 访客统计页

用途：展示 mock 访客统计结果。

布局：

- 移动端为统计卡片 + 趋势图 + 访客卡片列表
- PC 端为统计卡横排 + 全宽趋势图 + 表格列表

交互：

- 支持切换 `7天` / `30天` / `全部`
- 切换后更新趋势图与访客列表的本地展示结果

### 4. `/login` Key 登录页

用途：模拟后台访问入口。

布局：

- 移动端为全屏居中
- PC 端为浅灰背景中的居中白色卡片

交互：

- 输入任意非空 key 视为登录成功
- 登录状态存入 `sessionStorage`
- 成功后跳回目标受保护页面；若无目标页则跳到 `/edit`
- 空输入时显示前端校验提示

### 5. `/print` 打印页

用途：作为后续 PDF 导出或浏览器打印的静态落点。

布局：

- 只保留简历打印内容
- 不显示常规导航、登录入口、访客入口和编辑操作
- 版式按 A4 阅读场景组织，而不是照搬网页导航结构

交互：

- 本阶段不做真实导出
- 展示当前简历草稿的打印版内容

## 路由与守卫

定义 5 个页面路由：

- `/`
- `/edit`
- `/visitors`
- `/login`
- `/print`

受保护路由：

- `/edit`
- `/visitors`

守卫规则：

- 未登录访问受保护路由时跳转 `/login`
- 跳转时记录原始目标路由
- 登录成功后跳回该目标路由

登录状态判断：

- 只检查 `sessionStorage` 中是否存在前端登录标记
- 不调用真实接口

## 数据设计

### 简历数据

建立一份统一的简历 mock 数据对象，作为以下页面的共同数据源：

- `ResumePage`
- `EditPage`
- `PrintPage`

读取策略：

1. 先从 `localStorage` 读取当前草稿
2. 若本地无草稿或解析失败，则回退到内置 mock 数据

写入策略：

- 编辑页点击保存时，将当前草稿写入 `localStorage`

这样可以保证：

- 编辑结果能立即反映到展示页和打印页
- 第一阶段无需后端即可完成“编辑 -> 保存 -> 展示”的闭环

### 访客数据

访客统计页使用独立 mock 数据源，包括：

- 聚合统计卡数据
- 趋势数据
- 访客列表数据

访客数据不与简历数据共享状态，避免无意义耦合。

## 状态边界

### `sessionStorage`

存储短期登录态：

- 登录标记
- 登录前目标路由

关闭标签页后失效，符合总方案中的“临时后台访问”定位。

### `localStorage`

存储简历草稿：

- 当前简历对象
- 可选保存时间戳

用途是让用户刷新页面后仍能看到已编辑的本地内容，提升静态原型的可用性。

## 组件分层

建议目录按职责拆分，而不是按页面把所有内容堆在一起。

推荐结构：

```text
web/src/
  app/
  pages/
  components/
    common/
    layout/
    resume/
    editor/
    visitors/
  data/
  lib/
  styles/
```

各层职责：

- `pages/`：路由页面入口
- `components/layout/`：导航、容器、页面头部等布局模块
- `components/resume/`：展示页和打印页复用模块
- `components/editor/`：输入块、数组区块、标签编辑等编辑组件
- `components/visitors/`：统计卡、趋势图、访客列表等模块
- `data/`：mock 数据
- `lib/`：存储、守卫、格式化等工具函数

## 视觉与样式规则

遵循现有 Pencil 稿和总方案中的基础风格：

- 风格：简约、专业
- 主色：蓝色系
- 背景：移动端白色，PC 端浅灰
- 内容卡片：白底、轻边框或轻阴影
- 字体层级清晰，正文与辅助信息区分明确

样式实现原则：

- 用 Tailwind 完成页面主体结构和状态样式
- 对重复出现的颜色、圆角、阴影、间距抽成可复用 token 或语义类
- 保持移动端优先，再扩展到 PC 端布局

## 交互边界

本阶段保留“可操作感”，但不伪装成已接后端。

会做的交互：

- 登录表单前端校验
- 登录成功跳转
- 路由守卫
- 编辑保存反馈
- 技能和经历区块的新增删除
- 访客时间范围切换
- 展示页跳转打印页

不会做的交互：

- 真正的接口请求
- 服务端错误提示
- 真实导出下载
- 图表库级别的复杂交互

## 错误处理

尽管不接后端，本阶段仍处理最基本的异常分支：

- 登录输入为空时阻止提交并提示
- `localStorage` 数据损坏时自动回退到默认 mock 数据
- 编辑页新增空内容时做最小校验或提供空模板占位
- 受保护页面在无登录态下统一跳转，不让页面自行分散判断

## 验证方式

本阶段完成后需要至少覆盖以下验证：

### 构建验证

- TypeScript 编译通过
- Vite 构建通过
- 路由可正常访问

### 视觉验证

- 移动端页面结构与 Pencil 稿一致
- PC 端页面结构与 Pencil 稿一致
- `ResumePage`、`EditPage`、`VisitorsPage`、`LoginPage`、`PrintPage` 的信息层级清晰

### 交互验证

- 未登录访问 `/edit` 与 `/visitors` 会跳转 `/login`
- 登录成功后能返回目标页
- 编辑后保存成功，刷新后仍可读到草稿
- 展示页与打印页能反映当前草稿
- 访客页切换时间范围后内容发生变化

## 后续衔接

本阶段完成后，第二阶段再接入：

- 真实后端 API
- 真实 `X-Auth-Key` 验证
- 真实访客数据
- 真实 PDF 导出

为了减少返工，第一阶段实现时应避免把 mock 数据、存储逻辑和页面结构强耦合在一起。

## 验收标准

以下条件同时满足，可视为阶段一完成：

- 五个页面均可访问
- 移动端与 PC 端布局基本对齐设计稿
- 路由守卫和登录跳转按预期工作
- 编辑页可以修改本地简历草稿并保存
- 展示页和打印页读取同一份当前草稿
- 访客页能基于 mock 数据切换不同时间范围视图
- 项目能正常构建
