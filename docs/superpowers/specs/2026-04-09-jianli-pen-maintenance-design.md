# jianli.pen 维护设计

## 目标

基于当前项目已经实现的真实路由和页面状态，维护 `jianli.pen`，让设计稿重新和代码保持一致，并且把旧页面的样式与导航细节统一一轮，避免后续继续在失真的设计稿上迭代。

本次维护目标分为两部分：

- 补齐目前 `.pen` 中缺失的页面与关键状态
- 在不推翻现有视觉语言的前提下，统一旧页面的导航、标题区、卡片和状态表达

## 范围

### 路由范围

设计稿需要覆盖当前前端代码中的 8 个真实页面：

- `/` 简历展示页
- `/edit` 编辑页
- `/drafts` 草稿列表页
- `/drafts/:id` 草稿预览页
- `/visitors` 访客统计页
- `/settings` 设置页
- `/login` 登录页
- `/print` 打印预览页

### 设备范围

所有页面都需要补齐两套画板：

- 移动端
- PC 端

### 状态范围

状态补齐以“代码里真实存在、用户可感知、会影响页面结构或操作反馈”的状态为准。

每个页面至少需要有：

- `main` 主态
- `loading`

如果页面代码里存在以下状态，再补入设计稿：

- `empty` 或等价的无数据态
- `error`
- 明确的业务分支态
- 明确的进行中反馈态

例如：

- 设置页的 PDF 导出开关开 / 关
- 设置页的开关切换进行中
- 打印页的可下载 / 禁用导出
- 打印页的下载中
- 简历展示页的可导出 / 不可导出
- 编辑页的保存弹窗 / 保存成功反馈 / 保存失败提示

## 当前现状

### 代码中的真实页面

当前 `web/src/app/router.tsx` 中已经存在以下页面：

- `ResumePage`
- `EditPage`
- `DraftsPage`
- `DraftPreviewPage`
- `VisitorsPage`
- `SettingsPage`
- `LoginPage`
- `PrintPage`

### 当前 jianli.pen 的现状

当前 `jianli.pen` 顶层只包含以下画板：

- 移动端：简历展示页、简历编辑页、访客统计页、Key 登录页
- PC 端：简历展示页、简历编辑页、访客统计页、Key 登录页

缺失的页面包括：

- 草稿列表页
- 草稿预览页
- 设置页
- 打印预览页

同时，已有旧画板仍然停留在旧导航结构中，没有同步到当前代码中的：

- `简历 / 编辑 / 草稿 / 访客 / 设置`

## 设计原则

### 1. 采用“增量统一”而不是重建设计系统

本次不重做产品风格，不先抽象一整套组件库，也不推翻现有配色和卡片语言，而是在现有视觉体系上增量维护。

原因：

- 现有公开简历页的视觉风格已经稳定
- 这次核心目标是恢复设计稿与代码的一致性
- 当前 `.pen` 内没有可复用组件体系，直接重建会把任务从“维护设计稿”变成“重设计产品”

### 2. 新增页面必须看起来像原产品的一部分

新增页面需要延续已有设计语言：

- 浅灰背景
- 白色卡片
- 圆角容器
- 轻阴影
- 品牌蓝作为主强调色

但需要统一一轮这些旧页面中的不一致项：

- 顶部导航页签
- 页面标题与说明文案层级
- 卡片内外边距
- 按钮尺寸和按钮层级
- 空态、报错态和加载态表现

### 3. 设计稿命名要直接对应代码语义

新的画板命名不再只写“某某页面”，而要显式标注设备与状态，便于后续维护时快速对应到代码路由和页面分支。

命名规则统一为：

- `M-页面名-状态`
- `PC-页面名-状态`

例如：

- `M-草稿列表-main`
- `M-草稿列表-empty`
- `PC-设置-error`
- `PC-打印预览-disabled`

## 全局统一方案

### 顶部导航

PC 端后台页统一使用同一套顶部导航结构，和当前 `TopNav` 保持一致：

- 左侧：品牌标识 + `温庆京的简历`
- 中间：`简历 / 编辑 / 草稿 / 访客 / 设置`
- 右侧：`导出 PDF` 按钮；当页面不允许导出时保留占位，避免布局跳动

移动端不强行复刻 PC 导航，而是统一采用“页面级头部”模式，并按页面类型收敛成固定规则：

- 列表类后台页：`页面标题 + 简短说明`，不额外放全局导航
- 编辑类页面：`标题 + 关键主操作`
- 详情 / 预览类页面：`返回入口 + 标题 + 主操作`
- 设置与登录等单任务页面：`标题 + 说明`，操作跟随内容卡片

这样移动端后台页虽然不显示 `TopNav`，但头部信息层级仍然统一。

### 页面标题区

后台页统一采用：

- 页面标题
- 一句说明文案
- 右侧操作区或筛选区

这样新增页面和旧页面的头部结构一致，便于后续继续补功能。

### 卡片系统

所有后台页面统一为：

- 页面背景使用浅灰
- 内容区以白色卡片为主
- 卡片统一圆角和阴影
- 卡片标题、次级说明、操作按钮采用一致的层级与间距

### 状态表达

统一状态规则如下：

- `loading`：使用简洁的状态卡片或占位容器，不单独设计复杂骨架屏
- `empty`：使用空状态卡片，并给明确的下一步建议
- `error`：使用浅红背景的错误提示卡片，保持在页面容器内，不跳出到全页异常布局
- `toast`：用于保存成功等轻量反馈，沿用现有编辑页和设置页的提示风格

## 页面级设计定义

### 1. 简历展示页

补齐状态：

- `main`
- `loading`
- `pdf-enabled`
- `pdf-disabled`

维护重点：

- PC 顶部导航同步到当前代码
- 右上角导出按钮支持显示和隐藏占位两种形态
- 移动端保留当前阅读式排版，但补充底部导出按钮开 / 关两种态

### 2. 编辑页

补齐状态：

- `main`
- `loading`
- `save-draft-dialog`
- `save-success-toast`
- `save-error`

维护重点：

- 移动端顶部操作区同步当前代码语义：`取消 / 保存为草稿 / 保存主简历`
- PC 端标题区统一为“标题 + 说明 + 操作区”
- 现有信息卡片、表单间距、标题层级统一

### 3. 草稿列表页

补齐状态：

- `main`
- `loading`
- `empty`
- `error`

主态需要体现每条草稿的：

- 草稿名称
- 草稿备注
- 更新时间
- `预览`
- `设为主简历`
- `删除草稿`

### 4. 草稿预览页

补齐状态：

- `main`
- `loading`
- `error`

主态结构为：

- 页面头部草稿信息
- 返回草稿列表
- 设为主简历
- 下方简历预览

此页不单独设计 `empty`，因为代码逻辑里以错误态收口。

### 5. 访客统计页

补齐状态：

- `main`
- `loading`
- 范围切换后的主态表现

维护重点：

- 统一标题区和时间范围按钮
- 统一统计卡片、趋势图、列表 / 表格卡片的节奏与边距
- 移动端强化纵向信息层次，PC 端保留仪表盘布局

### 6. 设置页

补齐状态：

- `main-enabled`
- `main-disabled`
- `loading`
- `saving`
- `error`
- `save-success-toast`

这是本次新增的后台页之一，设计上延续后台卡片风格，重点表达：

- 页面标题与说明
- `站点设置` 卡片
- `允许访客导出 PDF` 开关
- 开关说明、切换中的反馈与保存结果反馈

### 7. 登录页

补齐状态：

- `main`
- `submitting`
- `error`

维护重点：

- 沿用居中登录卡片
- 统一输入框、主按钮和错误提示的视觉层级
- 保持“轻后台”风格，与其余后台页一致

### 8. 打印预览页

补齐状态：

- `main-enabled`
- `main-disabled`
- `loading`
- `downloading`
- `download-error`

维护重点：

- PC 端突出顶部说明区 + 下载按钮 + A4 预览
- 移动端保持同样语义，但压缩成单列
- 当 PDF 导出关闭时，保留页面说明与预览内容，但隐藏下载按钮

## 画板组织方案

顶层画板会按页面和设备重新组织，至少形成以下结构：

- 一组移动端画板
- 一组 PC 端画板

每组内部按页面归类，并使用统一命名规则标识状态。

旧的简历展示页、编辑页、访客页、登录页不会直接删除重来，而是优先复制并修整到新的命名和结构下，减少风格漂移。

缺失页面将新增完整画板。

## 实施顺序

建议在 `.pen` 中按以下顺序维护：

1. 先设置所有目标画板的占位框与排布位置，避免与现有画板重叠
2. 先统一 PC 端后台导航与页面头部结构
3. 补齐缺失的 PC 页面与状态
4. 补齐移动端缺失页面与状态
5. 回头修整已有移动端 / PC 旧页面的导航、标题区和状态表达
6. 对关键画板逐个截图检查，确认没有排版错位

## 验收标准

- `jianli.pen` 覆盖当前代码中全部 8 个页面
- 每个页面都有移动端和 PC 端画板
- 每个页面都补齐主态与代码中真实存在的关键状态，且状态定义和代码行为一致
- 旧页面导航同步到当前代码结构
- 新旧页面的卡片、标题区、按钮和状态提示风格统一
- 设计稿命名规则清晰，可直接映射到路由、设备和状态
- 最终画板布局不重叠，截图检查无明显错位或裁切问题

## 非目标

- 不修改前端代码
- 不在这轮里引入完整 reusable 组件系统
- 不追加代码中尚未实现的新功能页面
- 不对现有产品做风格重设计
