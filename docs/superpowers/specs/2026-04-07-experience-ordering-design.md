# 经历顺序调整设计

## 概述

当前编辑页中的工作经历、教育经历、项目经历只能新增、删除和修改内容，无法调整条目顺序。由于公开简历页、打印页和草稿预览页都直接按数组顺序渲染，这导致管理员无法控制同类经历的展示优先级。本次改动为三类经历列表新增“上移 / 下移”能力，使管理员可以在编辑页内直接调整条目顺序，并在保存后让所有展示端统一跟随。

## 目标

- 编辑页中的工作经历支持上移 / 下移
- 编辑页中的教育经历支持上移 / 下移
- 编辑页中的项目经历支持上移 / 下移
- 顺序调整后直接更新当前编辑态，不需要额外确认
- 保存主简历后公开页、打印页、草稿预览页统一按新顺序展示
- 保存草稿后草稿详情预览也保持相同顺序

## 非目标

- 不做拖拽排序
- 不做“置顶 / 置底”
- 不做跨类型排序，例如工作经历与项目经历之间互换
- 不新增后端字段或排序权重结构
- 不增加排序操作的单独 toast

## 核心思路

顺序信息直接由数组本身表达：

- `resume.workExperience` 的数组顺序即工作经历展示顺序
- `resume.education` 的数组顺序即教育经历展示顺序
- `resume.projects` 的数组顺序即项目经历展示顺序

编辑页点击“上移 / 下移”时，只交换对应数组中相邻项的位置。由于现有展示页、打印页和草稿预览页本来就直接按数组顺序渲染，因此不需要额外引入排序字段或排序逻辑。

## 交互设计

### 编辑页

在以下三个列表中为每个条目增加排序操作：

- 工作经历
- 教育经历
- 项目经历

每个条目头部操作区调整为：

- `上移`
- `下移`
- `删除`

行为规则：

- 第一项的 `上移` 按钮禁用
- 最后一项的 `下移` 按钮禁用
- 中间项两个按钮都可用
- 点击后立即在页面上反映新的顺序
- 不弹窗、不二次确认、不额外 toast

### 为什么不加 toast

顺序调整属于直接可见的界面操作，点击后卡片位置会立刻变化，已经构成足够清晰的反馈。额外 toast 反而会增加噪音。

## 数据与持久化

### 前端编辑态

编辑态仍使用当前 `ResumeData`：

- 不新增排序字段
- 不改变 `WorkExperience`、`EducationExperience`、`ProjectExperience` 的结构

### 后端持久化

后端无须新增接口或数据库字段：

- 保存主简历时，仍然保存完整的 `ResumeData`
- 保存草稿时，仍然保存完整的 `ResumeData`
- 调整顺序后的数组会原样写入后端

## 展示端影响

### 公开简历页

公开简历页继续按数组顺序渲染：

- `workExperience` 顺序变化后，公开页工作经历顺序跟随
- `education` 顺序变化后，公开页教育经历顺序跟随
- `projects` 顺序变化后，公开页项目经历顺序跟随

### 打印页

打印页继续按数组顺序渲染，因此保存后的新顺序自动生效。

### 草稿预览页

草稿预览页使用草稿中的 `ResumeData` 渲染，因此保存草稿时的排序结果也会被保留并正确展示。

## 代码边界

### 编辑组件

优先在编辑页本身增加一个小而明确的数组交换辅助函数，例如：

- `moveItemUp(list, index)`
- `moveItemDown(list, index)`

或提炼为一个通用的小工具函数：

- `moveArrayItem(list, fromIndex, toIndex)`

要求：

- 只负责交换数组顺序
- 不掺杂 UI 文案和事件逻辑
- 保持纯函数，便于测试

### 列表组件

`EditableListSection` / `EditableListItem` 可以扩展头部操作区能力，但不要让组件承担具体的数据交换逻辑。排序动作的业务逻辑仍建议由 `EditPage` 持有，以便不同列表复用统一模式。

## 错误处理

排序操作属于纯前端内存态变更，不涉及即时网络请求，因此：

- 不需要新增接口错误处理
- 禁用按钮即可避免越界移动
- 若索引非法，辅助函数应直接返回原数组，避免抛异常影响交互

## 测试边界

### 前端自动化测试

至少覆盖：

- 工作经历点击 `下移` 后，两个条目的显示顺序交换
- 教育经历第一项的 `上移` 为禁用状态
- 项目经历最后一项的 `下移` 为禁用状态
- 调整顺序后执行“保存主简历”，提交的 payload 中数组顺序正确
- 调整顺序后执行“保存为草稿”，提交的 payload 中数组顺序正确

### 展示层验证

建议补至少一项回归测试，证明展示层遵循数组顺序：

- 传入手工调整后的 `workExperience` 或 `projects` 数组，确认公开页或打印页渲染顺序与数组顺序一致

由于当前展示组件本身已是直接 `map` 输出，这部分测试可以控制在较小范围，不需要过度重复。

### 人工联调

需要确认：

- 编辑页中三类经历都可上移 / 下移
- 禁用态按钮不可点击
- 保存主简历后公开页顺序同步更新
- 保存草稿后草稿预览页顺序正确
- 打印页顺序与编辑结果一致

## 验收标准

满足以下条件视为完成：

- 工作经历、教育经历、项目经历都支持上移 / 下移
- 第一项上移禁用，最后一项下移禁用
- 顺序调整在编辑页即时可见
- 保存后公开页、打印页、草稿预览页顺序统一跟随
- 不引入新的数据字段或额外排序协议
- 相关前端测试通过
