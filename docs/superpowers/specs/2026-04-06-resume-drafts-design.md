# 简历草稿版本管理设计

## 概述

当前系统只有一份“主简历”，管理员在编辑页保存后会直接覆盖线上展示内容，缺少中间态版本管理能力。本次改动新增“后端持久化草稿”能力，使管理员可以在编辑过程中将当前变更保存为草稿，在草稿页查看所有历史草稿，并对单个草稿执行预览或切换为当前主简历。

## 目标

- 编辑页支持将当前表单内容保存为草稿
- 草稿数据持久化到后端数据库
- 草稿列表页仅管理员可访问
- 草稿列表支持查看名称、备注、创建时间、更新时间
- 管理员可预览单个草稿的完整内容
- 管理员可将某个草稿切换为当前主简历
- 草稿切换为主简历后，草稿记录仍保留
- 管理员可删除不再需要的草稿版本

## 非目标

- 不做草稿差异对比
- 不做草稿分页、搜索、筛选
- 不做草稿覆盖更新，首版只创建新草稿
- 不做多角色权限系统，沿用现有管理员认证
- 不做“发布历史”或主简历历史回滚

## 数据模型

### 主简历

保留现有主简历存储方式：

- 表：`resume_records`
- 语义：系统当前唯一对外展示的主简历
- 行为：`GET /api/resume`、`PUT /api/resume` 继续读取和覆盖这份数据

### 草稿

新增草稿表，例如：

```sql
resume_drafts
- id
- name
- note
- data
- created_at
- updated_at
```

字段语义：

- `id`：草稿主键
- `name`：管理员填写的草稿名称，必填
- `note`：管理员填写的草稿备注，选填
- `data`：该草稿对应的完整简历 JSON
- `created_at`：创建时间
- `updated_at`：更新时间，首版主要等于创建时间，后续若支持覆盖草稿可继续复用

## 核心行为

### 保存主简历

编辑页点击“保存主简历”时，沿用当前逻辑：

- 前端调用 `PUT /api/resume`
- 后端覆盖主简历记录
- 对外展示页立刻读取到最新主简历

### 保存为草稿

编辑页点击“保存为草稿”时：

- 前端收集当前编辑中的完整简历数据
- 管理员填写草稿名称和备注
- 前端调用新增接口 `POST /api/resume/drafts`
- 后端创建一条新的草稿记录
- 主简历不发生变化

### 预览草稿

管理员进入草稿详情页后：

- 前端调用 `GET /api/resume/drafts/:id`
- 使用草稿的 `data` 渲染简历预览
- 该预览不影响主简历，不修改数据库中的主简历记录

### 切换为当前主简历

管理员在草稿页或草稿详情页点击“设为主简历”时：

- 前端调用 `PUT /api/resume/drafts/:id/publish`
- 后端读取该草稿的 `data`
- 后端用草稿 `data` 覆盖主简历记录
- 草稿自身保留，不删除、不归档

## 接口设计

### 公开接口

以下接口保持不变：

- `GET /api/resume`
- `GET /api/resume/pdf`

### 管理员接口

#### `POST /api/resume/drafts`

请求体：

```json
{
  "name": "面试前调整版",
  "note": "补充项目亮点和技能描述",
  "data": {
    "profile": {},
    "skills": [],
    "jobIntention": {},
    "education": [],
    "workExperience": [],
    "projects": [],
    "awards": []
  }
}
```

行为：

- 校验 `name` 非空
- 校验 `data` 可编码为合法简历 JSON
- 创建草稿记录并返回草稿详情

#### `GET /api/resume/drafts`

返回草稿摘要列表：

```json
[
  {
    "id": 12,
    "name": "面试前调整版",
    "note": "补充项目亮点和技能描述",
    "createdAt": "2026-04-06T10:00:00Z",
    "updatedAt": "2026-04-06T10:00:00Z"
  }
]
```

排序规则：

- 按 `updatedAt desc` 返回，最新草稿排在最前

#### `GET /api/resume/drafts/:id`

返回单个草稿详情：

```json
{
  "id": 12,
  "name": "面试前调整版",
  "note": "补充项目亮点和技能描述",
  "data": {},
  "createdAt": "2026-04-06T10:00:00Z",
  "updatedAt": "2026-04-06T10:00:00Z"
}
```

#### `PUT /api/resume/drafts/:id/publish`

行为：

- 读取指定草稿
- 若不存在则返回 `404`
- 将该草稿的 `data` 覆盖写入主简历
- 返回当前已切换成功的主简历内容，或返回草稿详情加发布成功标记

首版建议直接返回新的主简历内容，便于前端后续跳转或刷新状态。

#### `DELETE /api/resume/drafts/:id`

行为：

- 删除指定草稿
- 若不存在则返回 `404`
- 删除成功返回空响应或成功标记

## 权限设计

沿用现有管理员认证机制：

- 公开访问：`GET /api/resume`、`GET /api/resume/pdf`
- 需要管理员认证：所有草稿相关接口、现有 `PUT /api/resume`

前端页面权限同样沿用现有 `ProtectedRoute`：

- `/edit`：管理员可访问
- `/drafts`：管理员可访问
- `/drafts/:id`：管理员可访问

不新增角色、权限枚举或更复杂的会话系统。

## 前端页面设计

### 编辑页 `/edit`

当前编辑页保留“保存主简历”能力，并新增“保存为草稿”入口。

交互建议：

- 桌面端显示两个主要动作：
  - `保存为草稿`
  - `保存主简历`
- 移动端同样提供这两个动作，避免功能不一致
- 点击“保存为草稿”后展示轻量输入区域或弹窗，要求输入：
  - 草稿名称
  - 草稿备注

保存成功后：

- 展示 toast，如“草稿已保存”
- 不跳转离开编辑页
- 当前表单内容保持不变

### 草稿列表页 `/drafts`

页面职责是版本管理，不承担编辑功能。

列表信息：

- 草稿名称
- 草稿备注
- 创建时间
- 更新时间

每条草稿提供动作：

- `预览`
- `设为主简历`
- `删除`

空状态：

- 无草稿时显示明确提示，如“还没有保存过草稿”

### 草稿详情页 `/drafts/:id`

页面顶部展示草稿元信息：

- 草稿名称
- 草稿备注
- 创建时间
- 更新时间

页面主体复用现有简历展示组件渲染草稿 `data`，保证草稿预览和主简历展示一致。

页面动作：

- `设为主简历`
- `返回草稿列表`

可选保留 `删除`，但首版即使只在列表页提供删除也足够。

## 组件与代码边界

### 后端

建议新增或调整以下职责边界：

- `internal/model`
  - 新增草稿记录模型
- `internal/store`
  - 在 `ResumeStore` 中补充草稿相关方法，或拆出 `ResumeDraftStore`
  - 支持创建、列表、详情、发布、删除
- `internal/handler/resume.go`
  - 继续承载主简历接口
  - 增加草稿相关 handler，或拆分为独立草稿 handler
- `cmd/server/main.go`
  - 注册草稿路由到管理员保护分组

若 `resume.go` 文件继续膨胀，优先拆分草稿 handler，避免单文件职责过重。

### 前端

建议新增或调整以下职责边界：

- `web/src/lib/storage.ts`
  - 从“单份简历保存”扩展为“主简历 + 草稿接口访问”
- `web/src/hooks`
  - 现有 `useResumeDraft` 实际承载的是编辑中的简历数据
  - 可保留其职责为“编辑页简历加载与保存”
  - 另增草稿列表/详情 hook，避免单个 hook 同时处理所有草稿逻辑
- `web/src/pages/EditPage.tsx`
  - 新增保存草稿入口
- `web/src/pages`
  - 新增草稿列表页
  - 新增草稿详情页
- `web/src/app/router.tsx`
  - 注册 `/drafts`、`/drafts/:id`

## 错误处理

- 创建草稿时若 `name` 为空，返回 `400`
- 草稿不存在时：
  - `GET /api/resume/drafts/:id` 返回 `404`
  - `PUT /api/resume/drafts/:id/publish` 返回 `404`
  - `DELETE /api/resume/drafts/:id` 返回 `404`
- 未认证访问草稿接口时返回 `401`
- 前端加载草稿列表失败时显示错误提示，不静默失败
- 前端发布草稿成功后提示“已切换为当前主简历”

## 测试边界

### 后端 store

至少覆盖：

- 创建草稿后能读回完整内容
- 草稿列表按更新时间倒序返回
- 能读取单个草稿
- 能将草稿内容发布为主简历
- 删除草稿后列表中不再出现

### 后端 handler

至少覆盖：

- 草稿相关接口需要认证
- 创建草稿返回正确 payload
- 查询草稿列表与详情返回正确结构
- 发布草稿会更新 `GET /api/resume` 的返回内容
- 删除草稿成功
- 草稿不存在时返回 `404`

### 前端

至少覆盖：

- 编辑页点击“保存为草稿”会提交名称、备注和当前表单数据
- 草稿列表页能正确展示草稿摘要
- 草稿详情页能渲染草稿内容
- 点击“设为主简历”会调用发布接口
- 未登录访问 `/drafts` 或 `/drafts/:id` 会被拦截

### 人工联调

需要确认：

- 编辑页保存草稿后，公开简历页内容不变
- 发布某草稿后，公开简历页立即展示草稿内容
- 草稿保留在列表中，可再次预览
- 删除草稿后列表即时刷新

## 验收标准

满足以下条件视为完成：

- 管理员可在编辑页将当前内容保存为后端草稿
- 管理员可在草稿列表页看到所有草稿摘要
- 管理员可预览任意草稿的完整简历内容
- 管理员可将任意草稿切换为当前主简历
- 草稿切换后草稿记录仍保留
- 草稿列表与详情页仅管理员可访问
- 相关前后端自动化测试通过
